# Полноценная админ-панель Калерии

## Главная проблема сейчас

Каталог, главная и карточки товаров показывают фиксированный список из кода, а не то, что хранится в базе. Поэтому изменения в админке сейчас не видны на сайте. Это исправляется в первую очередь.

Фотографии тоже фиксированные: в админке есть только поле «ключ фотографии» из пяти заранее подготовленных снимков, загрузить свой файл нельзя.

## Что будет сделано

### 1. Сайт начнёт показывать то, что в админке
Главная, каталог и карточка товара будут брать товары из базы (только опубликованные). Если база пуста или недоступна, показывается текущий набор как запасной вариант.

### 2. Загрузка фотографий с компьютера
- Отдельное защищённое хранилище для фото товаров.
- В карточке товара в админке: перетащить или выбрать файл, увидеть превью, заменить или удалить.
- До 5 фотографий на товар, первая — главная; порядок меняется стрелками.
- Ограничение размера файла и типов (JPG, PNG, WebP), автоматическое сжатие крупных снимков перед загрузкой.

### 3. Заказы и заявки
Вкладка «Заявки» получает:
- поиск по имени, телефону, почте;
- фильтры по типу (заказ, расчёт, мастер-класс, сертификат, звонок) и статусу (новая, в работе, завершена);
- счётчики: сколько новых, в работе, завершённых;
- раскрытие заявки: весь состав корзины, параметры калькулятора, бюджет, сроки, удобный канал связи;
- внутренний комментарий администратора с сохранением;
- ссылки «позвонить» и «написать»;
- выгрузка списка заявок в файл для таблиц.

### 4. Управление ассортиментом
- Создание, редактирование, удаление товара (с подтверждением).
- Все поля: название, адрес страницы (создаётся автоматически из названия), категория выбором из списка, цена, короткое описание, подробности, уход, размеры, публикация, показ на главной.
- Порядок товаров в каталоге задаётся вручную.
- Поиск по названию и фильтр по категории, быстрый переключатель «на сайте / скрыт».
- Проверка полей перед сохранением и понятные сообщения об ошибках.

### 5. Общее
- Боковое меню панели: Заявки, Товары; сверху — краткая сводка.
- Сохранение и ошибки показываются всплывающими уведомлениями.
- Панель остаётся доступной только учётной записи с правами владельца.

## Техническая часть

- Миграция: `products` получает `image_urls text[] default '{}'`, `sort_order int default 0`; индекс по `sort_order`. Существующий `image_key` сохраняется как запасной вариант и помечается устаревшим.
- Миграция: `leads` — индексы по `status`, `created_at`.
- Хранилище: публичный bucket `product-images`; политики на `storage.objects` — чтение всем, запись/удаление только при `has_role(auth.uid(),'admin')`.
- Публичное чтение товаров: серверная функция с publishable-клиентом (`published = true`, сортировка по `sort_order`, затем `created_at`), маршруты `/`, `/catalog`, `/catalog/$slug` читают её через loader + `ensureQueryData`; `fallbackProducts` остаётся как fallback при ошибке.
- Админка разбивается на `src/routes/admin.tsx` + компоненты `admin/leads-panel.tsx`, `admin/product-form.tsx`, `admin/image-uploader.tsx`; запись идёт браузерным клиентом под RLS-политикой администратора.
- Сжатие изображения на клиенте через `canvas` до ширины 1600 px перед загрузкой в хранилище.
- Регенерация `src/integrations/supabase/types.ts` после миграции.

## Проверка

Вход администратором, загрузка настоящего файла с диска, создание товара, проверка его появления в каталоге и на карточке, смена статуса заявки и комментария — сквозной прогон в браузере.
